02 / BUSINESS PROBLEM

难点不在“筛商品”，
而在把经验说清楚。

一次大促选品，往往同时包含营销目标、类目经验和国家履约要求。运营要在多个口径之间反复转换，结果也难以复用。

原有工作方式

口头需求 → 找经验 → 配条件 → 反复试筛 → 人工核对

经验分散、口径不一，选少了也难定位原因。
Agent 辅助方式

需求结构化 → 知识取证 → 规则预估 → 人工确认 → 可解释交付

减少重复操作，同时保留运营的判断权。

KNOWLEDGE DESIGN

四层知识，分别回答四个问题。

点击展开，查看每层如何支持业务判断。

01 / 指标与标签知识卡这个指标究竟是什么意思？

记录指标 ID、字段来源、统计窗口、运算符、阈值及有效期。例如比较“低价”时采用类目相对口径，避免用同一价格线筛所有类目。

02 / 业务语言与指标映射“爆品”应该看哪些指标？

不是只看销量；结合业务目标，从销量、增长、转化、库存等候选中做取舍。“万圣节”先用于扩展检索，不直接凭联想生成硬筛选条件。

03 / 场景策略模板这个场景怎样开始配置？

提供国家、活动、类目与楼层对应的初始策略；标出可调整顺序、不可放宽项和待确认参数。模板是起点，需要结合当前供给重新预估。

04 / 历史选品 Case以前怎么改，为什么改？

记录规则、运营修改、筛选漏斗与后续结果。复用前检查适用场景、标签版本、有效期和当前商品供给，避免照搬旧阈值。

不自造规则

缺少知识或字段时说明缺口。

不擅自放宽

数量不足，先展示漏斗再确认。

不自动发布

圈选、保存与发布分开处理。
