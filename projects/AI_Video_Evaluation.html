02 / KEY FINDINGS

从生成结果，走向产品判断。

这是本次有限样本探索中最值得先被看到的四条结论。每条按「观察现象 → 真实证据 → 产品判断」呈现；没有可靠评分数据的地方，只做定性描述，不虚构结论。

01 / PROMPT 约束

Prompt 约束增加，不代表生成结果一定更好。

观察现象
WorkBuddy 转头实验中，约束最少的 A 与约束最完整的 C 都出现整体转动，C 还出现末帧跳变。
真实证据
A 极简描述→全身转动；B 详细描述首次全身转动、改用正面图首帧再次生成后才仅头部转动；C 强化约束→向左转动+末帧跳变。四段真实视频与 Agent 执行截图均在下方实验与对比页留档。
产品判断
B 同时改变了参考图和执行路径，不能把改善单独归因于 Prompt 结构；约束数量与生成稳定性之间不存在简单对应。
02 / 平台通道

同一基础模型，不同平台通道可能表现不同。

观察现象
MiniMax H3 经 WorkBuddy / Miora 通道调用与在 Miora 平台直接调用，画幅、背景和动作控制表现存在差异。
真实证据
场景 1 中 WorkBuddy/Miora 的 MiniMax H3 为 9:16、纯灰背景；Miora 平台同名模型为 3:4、背景未变纯灰、头身未保持。场景 5 转身任务两者结果也不同。
产品判断
只陈述观察到的差异，不推测平台内部算力、模型降级或 API 调参机制；选型时应把「平台通道」当作独立变量单独验证。
03 / 任务边界

没有适用于所有任务的绝对最优模型。

观察现象
同一模型在不同任务中的表现并不一致，任务难度越高差异越明显。
真实证据
转身场景中即梦 Seedance 2.0 Fast 与 2.5 都出现「无脚位变化」的转盘式转身；MiniMax H3 在拿苹果、行走任务表现稳定，却在转身中转了整圈；可灵多次出现额外表情与动作。
产品判断
应按具体任务（微表情 / 肢体 / 物理交互 / 行走 / 转身）分别选择候选组合，不做统一总排名。
04 / 真实成本

选型不能只看单次生成成本。

观察现象
价格更高的版本并没有在本样本中换来更好的转身结果。
真实证据
报告第 05 章成本核算显示即梦 Seedance 2.5 约 ¥7.2–7.6/次、2.0 Fast 约 ¥1.8–1.9/次，但两者转身样本都失败；WorkBuddy/Miora 通道部分任务经历拦截与重新提交。
产品判断
需把失败重试、生成效率、素材筛选和人工返工一并计入实际投入，而不是只比单次价格。

以上为本次条件下的探索性观察，受样本数量与随机性影响，不构成模型长期稳定性排名。

03 / EVALUATION DESIGN

不是谁最强，而是谁适合这一镜。

面向预算有限的AI短剧创作者，在相同场景的参考图和Prompt下，探索首次生成素材的可用性。比较对象是“模型 × 平台通道”的实际组合。

八项评价指标

统一输入下，对每次生成从以下维度定性观察。

01　指令遵循是否按指定的动作、顺序和约束生成。
02　角色一致性人物五官、服装、发型是否稳定。
03　动作合理性动作是否自然，有无额外动作。
04　视觉稳定性背景、画面比例与道具是否异常变化。
05　时间连续性动作是否连贯，有无跳帧与末帧突变。
06　成片可用性是否满足实际内容生产要求。
07　生成效率从提交到获得可用素材的过程。
08　成本获得可用素材所需的实际生成投入。
首次生成探索 ≠ 每个最终结果都来自首次提交

WorkBuddy部分任务经历审核与重新提交。页面区分首次提交与最终可用视频；不将“五类场景最终可用”转换为100%首次成功率。

成本之外，还有一个更早的问题


本次评测让我发现，创作者真正承担的并不只是单次生成费用，而是为了获得一条可用素材而付出的反复生成与筛选成本。不同镜头任务对模型和平台通道的要求不同，生成前却缺少一个足够直观的选型依据。

Agent自主执行更多步骤，并不必然意味着用户效率更高。对于存在潜在生成成本的任务，关键决策应该适时交还给用户。


实验总结 / 观察边界
本次实验中，Prompt 约束数量增加并未持续改善生成表现。Prompt B 同时改变了参考图与执行路径，并在结果检查、再次生成后才获得符合目标的版本；这不是严格的单变量对照实验，不能把结果改善完全归因于 Prompt 结构，也不能据此判断哪种 Prompt 结构更优。




从实验执行，到生成决策


早期实验进一步说明，生成结果不仅受 Prompt 影响，参考图、首帧驱动方式和执行路径也会改变结果。即使 Agent 能够自主检查和再次生成，也不意味着用户的整体成本一定降低。


创作者真正需要的，不只是失败后的修复，而是在生成之前就知道当前镜头有哪些风险、应该先调整什么，以及是否值得直接生成。






07 / AI PRODUCT EXPLORATION
方案探索 · 待验证
AI 视频生成前置决策助手
生成之前，先判断这一镜怎么做更稳。


这不是视频生成工具，也不是生成失败后的诊断工具，而是一款面向 AI 视频创作者的轻量级生成前决策辅助工具。


核心价值：将分散的模型评测经验转化为生成前可以直接使用的决策建议，减少盲目试错。


目标用户
使用 AI 视频工具进行短视频、AI 短剧及内容创作的创作者，尤其是需要反复生成多个镜头的内容生产团队。
核心痛点
  • 不知道某个复杂镜头适合什么模型。
  • 不清楚当前镜头有哪些容易失败的动作约束。
  • 不知道 Prompt 应该重点描述什么，哪些约束可能过于复杂。
  • 缺少结合实际评测证据的生成前建议。


唯一核心输入 · 一句镜头描述
我想让角色从正面向右转身90°，停留一秒后再转回正面，固定机位，4秒。
也可以直接粘贴已有 Prompt · 模型、平台、预算均为可选项 · 不需要上传视频或参考图


  1. 输入镜头描述用自然语言描述希望生成的动作，或直接粘贴 Prompt。
  2. AI 识别与预检识别任务类型、动作复杂度与潜在风险。
  3. 输出生成建议结合已有评测案例，给出任务分类、潜在风险、Prompt 优化、候选模型与平台组合、成本与生成注意事项。
  4. 用户确认并自行生成用户自行前往原视频平台执行。不实现自动视频生成、自动重试与自动视频分析。


CASE 01 / 转身镜头生成前预检
输入一句镜头描述，得到一份生成前建议


A 任务识别
大幅肢体动作 / 人物转身。


B 风险提醒
  • 转身过程中可能出现脚部没有配合移动的转盘式旋转。
  • 身体与头部可能不同步。
  • 可能出现人物整体畸变。
以上风险来自本项目第五类转身场景的实际观察；样本有限，不构成长期稳定性结论。


C 生成建议
  • 明确转身方向、角度及停留时间。
  • 补充双脚旋转和身体重心变化的动作描述。
  • 对动作准确性要求较高时，可以考虑拆分为两个镜头。


D 模型选择
结合本项目第五类转身场景的实际评测记录，展示有证据支持的候选模型与平台组合，并明确区分首次生成、再次生成与最终结果。不编造模型推荐排名。


E Prompt 优化
生成一份更清晰的动作描述，供用户复制：
固定机位，4秒，9:16竖屏。角色正面站立，向右转身90°，双脚随身体重心转动，转身后停留1秒，随后转回正面。全程保持人物比例与服装一致，动作连贯，不产生额外肢体动作。


本案例是产品交互方案示意，不是已实现功能。

产品边界、技术思路与验证方向

MVP 首期范围
做：自然语言镜头输入 · 五类任务场景识别 · 基于已有评测记录的规则匹配 · 小规模案例检索 · 潜在风险提示 · Prompt 优化 · 候选模型与平台建议。
不做：视频上传与多模态分析 · 自动抽帧 · 自动视频生成 · 自动多轮重试 · 复杂多 Agent 协作。


技术成本控制思路
采用「结构化规则库 + 小规模案例检索 + LLM」的轻量架构。优先通过规则识别常见任务和风险，仅在复杂描述、Prompt 冲突和需要生成建议时调用 LLM；案例检索只返回少量相关记录，不将全部视频、报告和历史上下文传给模型。不依赖视频多模态理解，降低使用门槛与推理成本。


产品验证指标（未来方向 · 待验证）
镜头任务识别准确率 · 风险提示有效性 · 建议采纳率 · 首次生成可用率 · 平均重试次数 · 单位可用素材成本 · 用户重复使用率 · 付费意愿。以上均为待验证指标，目前尚无实际数据。


商业化假设（待验证）
初期用户：个人创作者、AI 短剧团队。潜在方向：嵌入 AI 视频生成平台成为生成前置预检功能 · 为短剧及内容生产团队提供团队版服务 · 向其他 AI 创作工具提供模型选型与镜头预检 API。
商业化边界：当前仅完成有限样本的个人评测，尚未验证真实用户付费意愿及产品效果。后续需要通过用户测试、重试次数变化、素材成本变化和重复使用率验证商业价值。
