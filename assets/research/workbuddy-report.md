# Prompt 复杂度 ≠ 生成稳定性：一次针对 WorkBuddy 视频生成模块的评测实验

# **实验｜Prompt 对输出稳定性的影响**

**实验目标**：测试不同 Prompt 结构对角色转头视频生成质量和角色一致性的影响。

**agent生视频模型：** Miora 图生视频路线

**agent使用skill：**

- `design-router` — 设计路由，判断该走哪条生成路线

- `miora-creative-core` — Miora 创意核心，定义了输入规范、画布交付、质量门禁

- `miora-video-generation` — Miora 视频生成，定义文生/图生视频的具体流程

**固定条件**：

- 同一 IP 图片/三视图 

- 同一生成模型 

- 视频时长：4s 

- 动作：正面 → 缓慢向右转头 → 看向右前方 

- 固定镜头 

**变量：Prompt 结构**

- A：极简 

- B：详细描述 

- C：约束条件

**图片上传顺序依次为：**侧面、正面、背面

## **Prompt A \| 极简版**

**实验目标：**验证仅提供核心动作描述时，AI 是否能够准确执行目标动作，并保持角色原有外观稳定。

**提示词：**让图中的角色自然地向右侧缓慢转头，最后看向右前方。动作自然，持续4秒，镜头固定。

**观察：**角色头部脸部比例及服饰与三视图明显不符，并且全身随头部一起向右转转，动作出现错误，agent增加人物表情变化

## **Prompt B｜详细描述版**

**实验目标：**验证在增加角色外观一致性、动作范围及镜头约束后，能否减少模型对非目标区域的错误修改，并准确执行“仅头部向右转动”的指定动作。

**提示词：**（角色一致性约束）以输入图片中的角色为唯一主体，保持角色原有的外观、服装、发型和配饰不变。（角色一致性约束）

（动作约束）角色站立在原位置，先保持正面朝向镜头，然后自然地将头部缓慢向右侧转动，最终看向右前方。转头动作流畅、自然，不要突然移动。整个动作持续4秒。

（角色一致性约束）保持原有的紫色短发、齐刘海、黑色帽子、紫色眼睛、项链、黑色上衣、紫色百褶裙、腿环、白色长靴等视觉特征不变。

（镜头约束）镜头固定，画面构图保持不变，角色身体基本保持静止，仅进行自然的头部转动。

## **Prompt C｜约束条件版**

**实验目标：**验证增加明确的动作边界与负向约束（禁止身体转动、禁止改变外观等）后，能否进一步降低模型的非目标动作和角色特征变化。

**提示词：**基于输入图片生成一段4秒视频。

【动作】

角色保持站立姿态，身体、双手和双腿基本保持静止。

角色从正面朝向镜头开始，缓慢向右侧转动头部，动作连续且自然，最终看向右前方。

整个转头过程平滑，不要突然转动或大幅度移动。

【必须保持】

保持角色的身份和原始外观完全一致。

保持紫色短发、齐刘海、黑色帽子、紫色眼睛、脸部五官、耳朵、项链、黑色上衣、胸前樱桃图案、紫色百褶裙、腿部绑带、蝴蝶结和白色靴子的形状、颜色及位置基本不变。

保持角色身体比例和服装结构不变。

【禁止变化】

不要改变发型、发色、帽子形状或帽子位置。

不要改变脸部结构、眼睛大小、鼻子和嘴巴。

不要增加或减少手指、四肢或服装部件。

不要让头发大幅飘动或发生形变。

不要让帽子、项链、裙子、腿部绑带等配饰发生漂移、消失或生成。

不要让身体跟随头部大幅旋转。

【镜头】

固定机位，固定焦距，保持原始构图和角色位置。

不要推拉镜头、不要旋转镜头、不要改变背景。



整体动作自然、平滑、稳定，保持角色前后一致。

![image\.png](图片和附件/image%201.png)

**观察：**尽管Prompt增加了大量负向约束，但agent仍未准确理解动作边界，出现明显的非目标动作，人体整体向左旋转，且最后一帧出现跳变。

**视频生成效果：**[Prompt C\.mp4](图片和附件/Prompt%20C.mp4)

## 生成结果对比评测

基于动作准确性、角色一致性及画面稳定性，对三组 Prompt 的生成结果进行对比评估

**初步结论：** Prompt 约束增加并不必然带来生成稳定性提升。Prompt B 经结果检查和二次修正后达到交付要求，而 Prompt C 即使加入大量负向约束，仍出现明显的非目标动作与画面异常。

## 实验结论

**Prompt复杂度 ≠ 生成稳定性**

### AI视频生成具备完成基础任务的能力，但动作控制存在明显不确定性

在相同角色素材和任务目标下，Prompt A直接基于三视图生成视频时，出现了**人物整体转身、脸部变形、比例变化、服装及表情发生非预期变化**等问题，说明仅通过简单自然语言描述，AI较难准确控制复杂的局部动作。

### 增加角色一致性与动作约束后，生成结果有所改善

Prompt B进一步增加了**角色外观、服装、配饰、身体姿态及镜头等约束**，并通过两次生成进行对比。

其中：

- **全身转版本**：仍然出现身体跟随头部整体旋转的问题； 

- **仅头部转版本**：基本实现“身体保持静止，仅头部自然向右转动”的目标，可直接使用。 

说明**增加约束并进行多轮生成，可以显著提高任务成功率，但无法完全消除AI生成中的动作偏差。**

### Prompt C进一步强化“禁止变化”约束，但仍无法保证模型严格遵循指令

Prompt C进一步增加了禁止身体旋转、禁止面部变化、禁止服装/配饰变化等限制，但最终仍出现**人物整体向左旋转，与目标动作不一致**的情况。

这说明：

> **提示词约束能够降低非预期变化，但不能保证生成模型严格执行复杂的局部动作控制。**
> 
> 

因此，对于对动作准确性要求较高的视频任务，仅依赖一次生成并不可行，需要结合**结果检查 → 问题识别 → Prompt调整 → 重新生成**的迭代机制。

## 问题与建议

### 问题①：生成结果可控性不足

**表现：**

- 整体转身 

- 左右方向错误 

- 脸部变形 

- 服装变化 

- 表情变化 

- 非指令动作

**用户影响：**用户需要反复修改Prompt并重新生成，增加等待时间与生成成本，同时降低对Agent执行结果的信任。

**改进建议：**

加强结果校验 \+ 迭代生成机制

### 问题②：Agent 的「用户确认机制」不足

1. 当任务存在较高的不确定性、且生成成本较高时，Agent没有及时把关键决策交还给用户。

2. 如果每次视频生成均消耗独立的生成额度/积分，则Agent自主生成多个候选版本会增加资源消耗；即使实际计费机制不同，也会增加用户等待时间与无效生成成本。

3. Prompt B（为了提高成功率，直接生成两个候选方案）→**Agent效率 ≠ 用户效率**

    - agent视角→我多生成一个，成功率更高。

    - 用户视角→你多生成一个，我多花一次额度，还得自己筛选。

本次实验发现，Agent仅在首次任务中主动向用户确认技术方案，后续实验中则倾向于自主生成多个版本或直接执行。

**用户影响：**对于视频生成这类**生成成本较高、结果不确定性较强**的任务，如果缺少中间确认，可能导致：

**用户需求理解偏差 → 直接生成 → 结果不符合预期 → 产生无效生成成本 → 用户再次修改需求。**

**改进建议：**

1. 建议增加「生成前确认」机制

例如：

> **检测到该任务存在两种可行方案，预计分别需要生成一次视频。是否选择：**
> 
> A\. 仅头部转动
>  B\. 整体转身
>  C\. 两种都生成
> 
> 

而不是：

> “我觉得两个都不错，我帮你生成两个。”
> 
> 

2. 建立「自主执行 vs 用户确认」判断机制

**不是所有任务都应该“自主到底”，Agent的智能不仅体现在“会做”，也应该体现在“知道什么时候应该问用户”。**

**结论：**修改Agent产物原始文件名后，原任务中的视频引用出现异常，初步判断Agent对生成文件存在路径/文件名依赖。

**用户影响：**用户对生成文件进行常规管理操作后，可能导致历史任务中的产物失效。

**改进建议：**

Agent对生成文件使用稳定的内部文件ID进行引用，而非依赖用户可修改的文件路径/文件名；同时支持“重命名”操作同步更新内部引用。
